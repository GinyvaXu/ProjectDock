# 管理协议（ProjectDock Protocols）

> ProjectDock 把「一类文件夹怎么被管理」定义为**管理协议**：骨架 / 合规基线 / 菜单 / 版本方案 / 归档规则，全部由协议一处定义。
> 代码真源：`src/projectdock/protocols.py`。命名部分见 [命名规范.md](命名规范.md)。

---

## 2. 版本方案（version schemes）

| 方案 | 含义 | 识别方式 | 适用 |
|---|---|---|---|
| `semver` | 语义化版本 | `VERSION` + `CHANGELOG.md` + `versions/vX.Y.Z/dist/`；根 `dist/installer/build` 标「未归档构建」 | 软件/网站/游戏/脚本/其他 |
| `archive` | 日期归档 | `archive/v<序号>_<YYYYMMDD>/` 与 `versions/*` 作为归档批次；`dist/` 是**交付物**（不算未归档） | 资料系统 / 本地应用 |
| `upstream` | 上游只读 | 读取上游 `VERSION/CHANGELOG/versions` 只读展示；不标未归档、不提示本地发布 | 克隆仓库 |
| `none` | 不追踪 | 版本页显示「不追踪版本」 | 文档加工 / 工具脚本 |

- **按类型默认**，可在「编辑信息 → 版本方案」中按项目覆盖（空 = 跟随类型）。
- 归档排序：`v<版本>_<YYYYMMDD>` 按「日期 → 版本号」自然倒序（`v1.2_20260911 > v1.1_20260911 > v1_20260911`）。
- **版本归档要求不变**：覆盖前先归档、只增不删、不覆盖旧产物（见命名规范 §3）。

## 3. 命名风格与纳管

| 风格 | 规则 | 说明 |
|---|---|---|
| `classic` | `项目NN-类型-名称` | ProjectDock 经典三段式 |
| `local` | `ProjectN-名称` / `ProjectN.M-名称` | 本机 AIAgentBase 风格（类型存注册表） |
| `free` | 任意名称（排除点开头） | 自由命名：自动纳管资料库内全部非点开头文件夹 |
| `auto` | 自动识别 | 按现有项目判定（free 不参与识别；并列时用 classic） |

- 严格风格（classic/local）下，不符合风格的文件夹会出现在首页「**未纳管文件夹**」，可一键导入管理。
- **目录联接 / 符号链接**（如 `AgentFloat_build` → `Project3-AgentFloat克隆仓库`）自动跳过，避免同一实体重复纳管。
- 新建 / 重命名按当前风格并保留原序号；扫描兼容全部严格风格，切换风格不会丢项目。

## 4. 扩展点（新增协议 / 风格）

- **新增协议**：在 `protocols.py` 的 `PROTOCOLS` 登记一个 `Protocol`（骨架 + 合规 + 菜单 + 版本方案 + 归档规则），预设/合规/菜单/版本页自动生效。
- **新增命名风格**：在 `naming.py` 注册一个 `NamingStyle` 子类（`parse` + `make`），扫描/创建/重命名/API 自动生效。
- 自定义类型（界面「自定义类型」）目前提供 dirs/files/git 骨架；完整协议字段可在后续版本扩展。
