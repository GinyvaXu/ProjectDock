# 命名规范（AIAgentBase 本机资料库）

> 适用范围：`C:\AIAgentBase` 资料库及其下各项目。
> 本文是「本机项目管理逻辑」的命名部分总结，也是 ProjectDock「命名规范风格（naming styles）」功能的配套规范。
> **版本归档要求（第 3 节）是硬性要求，任何命名风格下都必须保留。**

---

## 1. 项目目录命名

### 1.1 规则

| 项 | 规则 | 示例 |
|---|---|---|
| 项目文件夹 | `Project<序号>-<名称>` | `Project1-大学信息收集管理汇总系统` |
| 子项目 | `Project<主序号>.<子序号>-<名称>` | `Project2.1-洛琪希美图分类` |
| 序号 | 不补零；新建取当前最大主序号 + 1；**重命名只换名称、序号原样保留** | `Project3-…` → `Project3-新名称` |
| 名称 | 中文 / 英文 / 数字；**不含空格**与 Windows 非法字符 `<>:"/\|?*` | `Project3-AgentFloat克隆仓库` |
| 类型 | **不进文件夹名**（类型记录在 ProjectDock 注册表，界面可改） | `Project1-…` 的类型可为「文稿」/「其他」 |
| 历史兼容 | ProjectDock 经典风格 `项目NN-类型-名称` 与本规范**同场兼容、可被扫描**，不强制改名 | `项目14-软件-ProjectDock` |

> 编号只用于排序与重命名保留；历史编号即使重复或跳号（如两个 `Project0-*`）也原样保留，不影响扫描与管理。

### 1.2 本机现有示例

```
C:\AIAgentBase\
├── Project0-ComfyUI
├── Project0-文档加工处理
├── Project1-大学信息收集管理汇总系统
├── Project2.0-图库管理
├── Project2.1-洛琪希美图分类
├── Project2.2-二次元图库管理
└── Project3-AgentFloat克隆仓库
```

## 2. 文件与目录命名

| 场景 | 规范 | 示例 |
|---|---|---|
| 日期 | 统一 `YYYYMMDD`（文件名 / 归档 / 批次） | `20260911` |
| 报告 / 数据产出 | `<主题>_<日期>.<扩展名>` | `四六级情况与规划_20260915.md` |
| 带版本交付物 | `<名称>_v<版本>_<日期>.<扩展名>` | `学业信息管家_模板资料包_v1.3_20260911.zip` |
| 文档迭代（草稿期） | `<名称>-v<n>.<扩展名>`（定稿后按上两行规范落盘） | `南京行程计划表-已订票版-v2.xlsx` |
| 覆盖式旧版 | `<原名去扩展名>_v<n>.<扩展名>`（进 `_archive/`，**不重复拼日期**） | `AGENT_PROMPT_v2.md` |
| 任务 / 批次子目录 | `YYYY.M.D-<主题>`（历史风格，保留兼容） | `2026.9.14-南京旅游` |
| 内部目录 | `_` 前缀：`_tools/`（工具链）、`_build/`（构建）、`_archive/`（归档）、`_stage_<YYYYMMDD>/`（临时区，用后即删） | `_tools/md2html.mjs` |
| 项目级说明文档 | 名称稳定、不带日期：`README.md`、`使用说明.md`、`需求与设计.md`、`项目状况报告.md` | — |

**禁止**：

- 文件名含空格；
- 覆盖式命名（`final`、`final2`、`最新版` 等无版本痕迹的名字）；
- 把令牌 / 明文个人标识写入临时区或文件名（临时区 `_stage_*` 用后即删）。

## 3. 版本归档要求（硬性 · 保留）

> 本节是本机规范的不可妥协项；ProjectDock 的版本/归档链路必须继续满足以下要求。

### 3.1 覆盖前先归档（不可破）

- 覆盖任何主文件（数据、报告、规范）前，先把旧版移入同级 `_archive/`；
- 归档名 = `<原名去扩展名>_v<n>.<扩展名>`，**不重复拼接日期**；
- 看板 / 失效项移入对应 `_archive/`；旧版规范留档（如 `archive/AGENT_PROMPT_v2.md`）。

### 3.2 版本留档

- 交付 / 发布批次：`archive/v<版本>_<YYYYMMDD>/`（如 `archive/v1.1_20260911/`）；
- 软件项目构建产物：`versions/vX.Y.Z/dist/`（二进制 / 散装包）、`installer/`（安装包）；
- 备份快照：`versions/backups/`（`pd_backup_*.zip`）；
- **只增不删、不覆盖旧产物**；同版本重建先带时间戳归档旧产物。

### 3.3 版本号与日志

- 软件项目 **`VERSION` 是版本号唯一来源**（纯数字 semver，如 `1.3.1`），禁止在源码 / 文档 / 安装器里手写第二份；
- 每次变更同步 `CHANGELOG.md`（`## [x.y.z] - 日期` + `### Added/Fixed/Changed` 分组）；
- 语义化版本：Bug 修复 = PATCH、新功能 / UI = MINOR、不兼容大改 = MAJOR。

### 3.4 临时区纪律

- 临时脚本 / 中间数据放数据根目录之外的 `_stage_<YYYYMMDD>/`；
- 临时区禁止沉淀明文姓名、账号、令牌；**用后即删**。

## 4. ProjectDock 命名规范风格（风格注册表）

ProjectDock 把「项目文件夹怎么命名」做成可插拔的**命名规范风格**，注册表在 `src/projectdock/naming.py`。

### 4.1 内置风格

| id | 名称 | 格式 | 示例 |
|---|---|---|---|
| `classic` | 经典三段式 | `项目NN-类型-名称` | `项目14-软件-ProjectDock` |
| `local` | 本机两段式 | `ProjectN-名称` / `ProjectN.M-名称` | `Project2.1-洛琪希美图分类` |
| `free` | 自由命名 | 任意名称（排除点开头） | `ProjectDock - 本地项目管理器部署` |
| `auto` | 自动识别 | 按资料库现有项目文件夹自动选择（默认；free 不参与识别） | — |

### 4.2 行为约定

- **扫描 / 导入始终兼容全部已注册（严格）风格** —— 切换风格不会丢项目；
- 新建 / 重命名按当前风格；`auto` 的识别规则：本机风格项目更多 → `local`，否则 `classic`（并列时用 `classic`）；
- `free` 自由命名：自动纳管资料库内全部非点开头文件夹；新建/重命名不加序号（标题即文件夹名）；
- 严格风格下，不符合风格的文件夹出现在首页「**未纳管文件夹**」，可一键导入管理；
- **目录联接 / 符号链接自动跳过**（同一实体的别名，避免重复纳管）；
- 重命名**保留原风格与原序号**（`Project2.1-…` 的子序号 `2.1` 原样保留）；
- 无类型风格（如 `local`）下，项目类型以 ProjectDock 注册表为准（界面可编辑）。

### 4.3 切换方法（当前版本）

| 方式 | 操作 |
|---|---|
| 设置文件 | `%APPDATA%\ProjectDock\settings.json` 的 `naming_style` 字段 |
| API | `PUT /api/settings` 传 `{"naming_style": "local"}` |
| API（查看） | `GET /api/naming/styles` 返回全部风格 + 当前值 + 自动识别结果 |
| CLI | `python -m projectdock.cli init <名称> --style local` |

### 4.4 新增风格（为未来版本预留）

1. 在 `src/projectdock/naming.py` 注册一个 `NamingStyle` 子类，实现 `parse(name)` 与 `make(index_raw, ptype, title)`；
2. 无需改动扫描 / 创建 / 重命名 / API —— 全部自动生效；
3. 未来版本的「一键切换」界面只需消费 `GET /api/naming/styles`，在设置里写入 `naming_style` 即可。

> 本机（AIAgentBase）推荐值：`naming_style = "auto"`（有本机风格项目时自动用 `local`）或显式 `"local"`；想自动纳管所有文件夹（含不符合风格的）用 `"free"`。
> 类型与版本方案见 [管理协议.md](管理协议.md)。
